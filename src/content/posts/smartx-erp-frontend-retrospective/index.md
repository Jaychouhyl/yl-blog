SmartX ERP 是我独立做的全栈项目：前端、Spring Boot 后端、Neo4j 图谱、RAG 助手、MCP 工具层，都是我一个人搭的。这篇主要记前端这部分的优化经过。

前端优化不是一次"把页面做漂亮"的任务。更准确地说，是把一个功能很多、风格不够统一的后台，往真正的企业运营控制台方向收。

我最初关注的是视觉问题：页面粗糙、卡片和阴影有点随意、不同模块像从不同模板里拼出来。但继续往下做才发现，真正的问题不是配色，而是系统缺少一致的表达规则。

## 高级感不是装饰

后台系统的高级感，来自稳定和克制。

表格密度要统一，按钮层级要稳定，状态色要有明确语义，弹窗不能每个页面一套结构，空态不能只留一片空白。用户每天要在这里查库存、看订单、看财务、问 RAG、点知识图谱，页面应该帮助他快速判断状态，而不是让他被装饰吸引。

所以这轮优化最重要的不是改某一个页面，而是把页面收回到 tokens、组件和布局规则里。颜色、间距、表格、Tag、Alert、Dialog、Drawer 都尽量服从同一套语言。

## 真实数据会暴露设计稿看不到的问题

静态页面很容易"看起来不错"。一接真实后端，问题会立刻出现。

比如客户和供应商字段出现乱码，图谱返回 0 实体，表格数据为空，接口代理和 CORS 出问题，Element Plus 在某些交互下有 warning。这些问题不是设计稿能提前发现的，也不是改几行 CSS 能解决的。

后端和图谱是我自己搭的，所以遇到问题能直接追到服务端和 Cypher 查询那层。企业后台的前端优化必须尽早进入真实数据环境——真实数据里的坏字符、空状态、异常接口和慢响应，才是后台系统真正的日常。

## 空态也是系统能力

知识图谱页面的 0 实体状态给我印象很深。

没有空态时，用户看到的只是空白。空白不会解释任何东西。更好的空态应该告诉用户：当前没有数据，可能是同步任务未跑、Neo4j 没连上、筛选条件太窄，或者确实还没有实体。它还应该告诉用户下一步能做什么。

空态不是插画和文案，而是系统在异常状态下的解释能力。

## AgentDock 应该是工具，不是主角

项目里有一个智能助手入口 AgentDock，是我设计和接入的。它很容易被做得很显眼，因为"AI 助手"听起来像亮点。

但在 ERP 里，主角应该是业务。助手应该随时可用，但不能挡住表格操作列，不能压过页面信息，也不能让用户觉得每个流程都必须先问 AI。

越智能的入口，越需要克制。它最好像一把顺手的工具，而不是一直抢镜的新功能。

## 这轮做完学到什么

从"页面好不好看"转向"系统好不好用"。UI 不是给截图服务的，它要承接真实数据、坏数据、权限、加载、错误、空态和复杂操作。

后续如果继续优化，我会先把坏数据问题追到数据源；补全站的 loading/empty/error/disabled 状态；把设计规则写进项目文档，避免下次又重新写散。
