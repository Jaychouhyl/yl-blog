# Snows-Blog 学习结论与忆霖博客改造设计

> 日期：2026-08-21
> 对象：`D:\yilin-blog` 与 [`zhifengmuxue/Snows-Blog`](https://github.com/zhifengmuxue/Snows-Blog)
> 状态：本轮视觉改造已实现并完成本地验证，进入最终视觉验收
> 边界：不修改文章正文，不迁移框架，不推送远端

## 1. 业务目标

本轮不是把忆霖博客迁移成 Hexo 或直接套用 Butterfly，而是研究 Snows-Blog 的信息架构与首页体验，从中提取适合当前 Astro 站点的小范围改进。

最终目标：

1. 首页首屏更纯净，第一眼只表达站点名称与内容方向。
2. 第一次向下滚动直接进入现有内容区，不出现首屏与内容区混杂。
3. 导航保持现有居中悬浮形态，并从“文章 / 项目”调整为“时间轴 / 标签 / 分类”。
4. 首页第二屏、主要列表页、关于页、文章详情页和项目详情页使用一致的作者信息结构。
5. 时间轴、分类、标签和关于页形成各自明确的主体布局，而不是只修改导航文字。
6. 使用真实内容数据展示网站资讯，不伪造访问量。
7. 所有公开 HTML 页面在主体内容结束后提供 Giscus 评论区。
8. 保留 Astro、现有文章目录、Pagefind、KaTeX、RSS、sitemap 和 GitHub Pages 工作流。

## 2. E1：Hexo、Butterfly、文章与配置的关系

Snows-Blog 的运行关系如下：

```text
package.json
  └─ Hexo 8 与生成器、渲染器、部署插件

_config.yml
  ├─ 站点信息、URL、固定链接
  ├─ 文章资源目录
  ├─ Feed、sitemap、搜索、MathJax
  └─ 部署目标

_config.butterfly.yml
  ├─ 导航、首屏、头像、侧栏
  ├─ 搜索、评论、数学公式
  └─ 主题组件开关与显示位置

source/_posts
  ├─ Markdown 文章
  └─ 与文章同名的资源目录

themes/butterfly
  ├─ Pug 页面模板
  ├─ Stylus 样式
  └─ 主题脚本与第三方集成
```

Hexo 负责读取内容和配置、生成路由与静态页面；Butterfly 负责页面结构、视觉表现和侧栏组件；插件补充固定链接、资源改写、搜索、Feed、sitemap、公式和部署。

忆霖博客对应关系：

| Snows-Blog | 忆霖博客 |
|---|---|
| `_config.yml` | `astro.config.mjs`、`src/config.ts` |
| `_config.butterfly.yml` | Astro 组件、页面和 CSS |
| `source/_posts` | `src/content/posts` Content Collection |
| Butterfly Pug 模板 | `.astro` 页面与组件 |
| Hexo 生成器插件 | Astro 路由、RSS、sitemap、Pagefind |

## 3. E2：写作流程对比

### Snows-Blog

1. 使用 `hexo new` 创建 Markdown。
2. 文章 front matter 由 scaffold 提供基础字段。
3. Hexo 在生成阶段读取文章、分类、标签和插件配置。
4. 字段约束主要依靠写作者约定与插件行为。

### 忆霖博客

1. 每篇文章使用 `src/content/posts/<slug>/index.md`。
2. Astro Content Collections 使用 Zod 校验 `title`、`date`、`tags`、`category`、`series`、`cover`、`draft` 等字段。
3. `generateId` 从目录名产生稳定 slug。
4. 草稿在 `publishedPosts()` 中集中排除。

### 判断

Hexo 命令式创建更方便；Astro 的 schema、类型提示和构建期校验更可靠。当前没有迁移写作系统的收益，应保留 Astro Content Collections。[Astro Content Collections 文档](https://docs.astro.build/en/guides/content-collections/)

## 4. E3：文章图片与同名资源目录

Snows-Blog 启用了：

- `post_asset_folder: true`
- `marked.prependRoot: true`
- `marked.postAsset: true`
- `hexo-asset-img`
- `hexo-image-link`

因此文章可以使用“文章文件 + 同名目录”管理图片，插件在生成阶段调整引用。[Hexo 资源目录文档](https://hexo.io/docs/asset-folders)

忆霖博客已经使用更接近 Astro 的同目录方式：

```text
src/content/posts/hello-world/
├─ index.md
└─ cover.webp
```

这与 Snows-Blog 的核心思路一致，但 Astro 会对通过内容 schema 导入的图片进行校验和优化。无需复制 Hexo 的图片改写插件；后续文章图片应优先与 `index.md` 同目录，只有真正的全站公共素材才放 `public/`。

## 5. E4：首页、导航、文章页与侧边栏

### 值得借鉴

- 首页 Hero 严格占满一个视口。
- 内容区从第二屏开始。
- 首次向下滚动直接定位到内容区和固定导航下方。
- Hero 只保留站名和一行动态副标题。
- 时间轴、标签、分类成为一级导航。
- 作者信息在首页内容区、归档、分类、标签、关于和详情页保持稳定位置。
- 公告、最近文章和网站资讯采用少量、固定的侧栏组合。

### 不直接照搬

- 不复制 Butterfly 的全部归档、第三方卡片和统计组件；只借鉴已明确确认的公告、最近文章、标签云和网站资讯结构。
- 不把当前首页改成通用浅色技术博客模板。
- 不更换当前书法背景、衬线字体和现有内容区卡片。
- 不把主题所有功能变成配置开关。

## 6. E5：分类、标签、搜索、Feed、sitemap 与固定链接

| 能力 | Snows-Blog | 忆霖博客 | 结论 |
|---|---|---|---|
| 时间轴 | Hexo archive generator | `/posts/` 已按年份分组 | 改导航名称，优化页面布局，不新建重复数据源 |
| 分类 | category generator | `/categories/` 与动态分类页已存在 | 直接复用 |
| 标签 | tag generator | `/tags/` 与动态标签页已存在 | 直接复用 |
| 搜索 | Hexo 本地搜索 XML | Pagefind 构建索引 | 保留 Pagefind |
| Feed | `hexo-generator-feed` | `@astrojs/rss` | 保留当前 RSS |
| sitemap | `hexo-generator-sitemap` | `@astrojs/sitemap` | 保留当前过滤规则 |
| 固定链接 | `hexo-abbrlink` 生成短标识 | 目录 slug 生成可读稳定路径 | 不迁移；目录 slug 更透明 |

当前站点已经具备上述能力，主要缺口是导航表达、统一侧栏和页面视觉组织，不是底层生成能力。

## 7. E6：MathJax 与 KaTeX

Snows-Blog 使用 `hexo-filter-mathjax`，Butterfly 开启 MathJax；忆霖博客使用 `remark-math + rehype-katex + KaTeX`。

| 维度 | MathJax | KaTeX |
|---|---|---|
| 兼容范围 | TeX/MathML 生态和扩展能力更广 | 覆盖常用公式，少数命令不支持 |
| 执行方式 | 通常在浏览器运行并加载组件 | 当前项目构建期生成 HTML |
| 首屏成本 | 配置不当会增加客户端脚本与渲染成本 | 当前方案无需公式运行时脚本 |
| 当前适配 | 适合复杂公式兼容要求 | 更适合当前静态博客和性能目标 |

KaTeX 的支持范围可以通过其[官方支持列表](https://katex.org/docs/supported.html)核对；MathJax 的输入、输出和组件体系见[官方文档](https://docs.mathjax.org/en/latest/basic/mathjax.html)。当前文章没有证明 KaTeX 存在阻塞，因此不迁移到 MathJax。

## 8. E7：主题配置与组件扩展

Butterfly 将大量能力集中在 `_config.butterfly.yml` 中，通过 Pug 模板按开关装配。这适合通用主题，但会形成庞大配置表和主题内部依赖。

忆霖博客应继续使用显式 Astro 组件：

- `Nav.astro` 管理导航。
- 首页 Hero 保留在 `index.astro`，因为它只属于首页。
- 新建一个共享页面侧栏组件，组合已有作者卡与网站资讯。
- 页面通过明确导入使用侧栏，不增加通用插件系统。

只有站点名称、导航项、Hero 文案等跨组件数据进入 `src/config.ts`；单页样式和行为保留在对应组件中。

## 9. E8：部署方式对比

Snows-Blog 使用 `hexo-deployer-git`：本地执行 `hexo deploy`，根据 `_config.yml` 的 SSH 仓库和分支直接发布。[Hexo 一键部署文档](https://hexo.io/docs/one-command-deployment)

忆霖博客使用 GitHub Actions：

```text
push main
  → npm ci
  → npm run build
  → upload-pages-artifact
  → deploy-pages
```

当前方式的构建环境和部署记录可复现，不依赖个人电脑 SSH 状态。应保留现有 GitHub Pages Workflow，不引入 `astro deploy` 或本地直推发布分支。

## 10. E9：借鉴与迁移清单

### 值得借鉴

1. 首屏严格占满视口。
2. 第一次滚轮直接切到内容区。
3. 居中站名与循环打字副标题。
4. 时间轴、标签、分类一级导航。
5. 主要内容页统一作者侧栏。
6. 使用文章数、分类数、标签数、字数和最近更新等真实站点资讯。

### 不适合迁移

1. Hexo 框架和 Butterfly 整体主题。
2. Pug、Stylus 与大体量主题配置。
3. Hexo 图片路径改写插件。
4. MathJax 客户端渲染。
5. `hexo-abbrlink` 固定链接。
6. 本地 `hexo deploy` 发布。
7. Twikoo、随机第三方句子和无明确需求的主题集成。

### 当前可以改进

1. 首页 Hero 信息过多，视觉焦点不明确。
2. 导航未直接暴露已有分类和标签能力。
3. `/posts/` 已是时间轴，但名称仍是“文章”。
4. 分类、标签和详情页缺少稳定的作者入口。
5. 已有 `SiteStats.astro`，但没有形成统一的网站资讯卡使用规则。

## 11. E10：确认实施的功能组

### 11.1 首页首屏

- 背景图片、对象位置和轮播能力保持不变。
- Hero 高度保持 `100vh / 100svh`。
- 删除当前 kicker、大标题说明、用途标签和三个操作按钮。
- 居中显示 `Yilin Blog`。
- 使用当前字体变量 `var(--serif)`，不引入新字体。
- 动态文字仅占一行，循环播放：
  1. `记录项目、琐碎、AI`
  2. `微服务、前端、后端、AI 学习琐碎`
- 动画规则：逐字输入、停顿、逐字删除、切换下一句。
- 文字中心使用柔和暗色径向遮罩提高对比度。
- 不使用黑色描边，不增加玻璃卡片或纯色文字底板。
- `prefers-reduced-motion: reduce` 时显示第一句静态文字。

### 11.2 首屏滚动

- 页面顶部第一次向下滚动时拦截默认滚动。
- 一次定位到现有 `#home-content` 起点。
- 动画期间设置短锁，防止连续滚轮造成抖动。
- 点击底部箭头执行相同行为。
- 离开首屏后恢复浏览器正常滚动。

### 11.3 首页内容区

`#home-content` 保留双栏结构、文章卡片、字体和间距，不因首屏施工重构文章内容。

左侧现有卡片只做已确认的补充：

1. 作者卡补充文章、标签、分类数量。
2. 作者卡只保留一个整行 `Follow Me` 按钮，按钮前使用 GitHub Octocat 图标，链接固定为 `https://github.com/Jaychouhyl`。
3. 删除作者卡中的 RSS 和重复 GitHub 小标签。
4. 站点公告继续保留。
5. “最新文章”只显示按发布日期倒序的最近 3 篇已发布文章。
6. 网站资讯追加在原有侧栏内容之后，不挤入 Hero，也不改变右侧文章顺序。
7. 首页评论区放在右侧主体内容结束后。

### 11.4 导航

保留现有导航字体、整体居中、透明效果、圆角玻璃悬浮形态、深浅色行为和移动端菜单。禁止改成品牌靠左、菜单靠右的通栏导航。

- Hero 可见时，导航仍是居中的透明形态。
- 离开 Hero 后，导航仍是居中的圆角玻璃悬浮形态。
- 搜索图标单独放大到约 `19px`，导航高度、间距和主题图标大小不变。
- 只调整入口，不改变搜索和主题切换逻辑。

| 标签 | 路径 |
|---|---|
| 首页 | `/` |
| 时间轴 | `/posts/` |
| 标签 | `/tags/` |
| 分类 | `/categories/` |
| 关于 | `/about/` |

项目页面继续保留，只是不再占用一级导航入口。

### 11.5 统一作者侧栏

统一侧栏适用于所有面向读者的公开 HTML 页面，包括首页第二屏、时间轴、分类、标签、系列、关于、项目、友链、相册、知识图谱及各类详情页；只排除 `404` 和机器端点。友链、相册、知识图谱等专用页面保留自身主体功能，只在外层加入相同侧栏，不重写内部内容。

通用侧栏顺序固定为：

1. 作者卡：已确认头像、忆霖、`项目 · 琐碎 · AI`、文章/标签/分类数量、`Follow Me`。
2. 站点公告：复用当前公告内容。
3. 最新文章：只显示最近 3 篇已发布文章的标题和日期。
4. 网站资讯：显示真实可计算数据。

桌面端侧栏位于左侧；移动端主要内容优先，整组侧栏移动到正文和评论区之后，不挤压正文宽度。共享侧栏优先复用现有组件，不复制 Butterfly 全套卡片。文章详情页使用专用组合顺序，见 11.11。

### 11.6 网站资讯

只显示能够从当前仓库计算的真实数据：

- 已发布文章数。
- 唯一标签数。
- 唯一分类数。
- 总字数。
- 运行天数或最近更新时间。

不显示访客数、总访问量等当前没有可靠数据源的指标。

### 11.7 时间轴

`/posts/` 不只是把“文章归档”改名为“时间轴”，主体改为明确的纵向时间轴：

- 标题显示“时间轴”和已发布文章总数。
- 按年份分组，年份作为一级节点。
- 每篇文章显示 `MM-DD`、标题和可选分类标记。
- 使用连续竖线和圆形节点表达时间关系。
- 时间轴页不再同时堆放顶部标签云与分类条，标签和分类由各自页面负责。
- 数据继续来自 `publishedPosts()` 与 `groupByYear()`，草稿不进入时间轴。

### 11.8 分类

`/categories/` 右侧主体使用分类总览列表，而不是普通文章卡片或只有标题的空页面：

- 每一项显示分类名称、文章数量和一句简短说明或最近内容提示。
- 数量来自 `allCategories()`，分类详情仍链接到现有动态路由。
- `/categories/[category]/` 在同一双栏布局中显示该分类的文章列表。
- 当前真实分类数量较少时不伪造分类填充版面。

### 11.9 标签

`/tags/` 右侧主体使用有层级的标签云：

- 标签字号按文章数量分级，不使用随机大小。
- 使用固定色板、不同字体、轻量描边、块面、旋转和位置偏移形成更跳脱的层次；样式按索引稳定生成，不使用刷新即变化的随机值，并为旋转后的视觉边界保留独立间距，标签之间不能粘连。
- 每个标签仍链接到 `/tags/[tag]/`。
- 标签详情页使用同一双栏布局显示对应文章列表。
- 标签和次数来自 `allTags()`，不建立第二套统计数据。

### 11.10 关于

`/about/` 使用与内容页相同的左右结构：

- 左侧显示统一作者侧栏。
- 右侧标题为“关于”，正文依次介绍忆霖、博客记录内容、当前关注方向和公开联系方式。
- 关注方向至少覆盖微服务与后端、前端与体验、AI 学习、项目与琐碎记录。
- 公开联系方式使用已确认的 GitHub 主页和 `hyl92186009@gmail.com`。

### 11.11 文章与项目页面

- 文章详情和项目详情均采用左侧统一侧栏、右侧正文的双栏结构。
- 文章详情页左侧依次显示作者卡、站点公告、目录、最近 3 篇文章和网站资讯；目录与正文并排，不再悬浮在正文右侧。
- 文章详情页最上方使用现有背景图作为标题横幅，叠加更明显的暗色遮罩，居中显示文章标题、发布日期、阅读时长、分类和标签。
- 文章详情、时间轴、标签、分类和关于页的标题背景区使用相同高度：桌面端约 380–500px，移动端 340px，为居中导航和页面标题留出明确间距。首页全屏 Hero 不受影响。
- 文章详情页左栏恢复通用的约 250px 宽度；卡片继续使用清晰的无衬线字体和调整后的信息层级，目录标题右侧显示随正文滚动更新的阅读进度（0–100），阅读辅助区保留滚动能力但不显示可见滚动条。
- 桌面端滚动到目录完整进入视口后，目录、最近文章和网站资讯组成的阅读辅助区保持吸顶；辅助区超过可视高度时在区内滚动，正文继续独立向下阅读。
- 移动端不固定整组侧栏，保留右下角“目录”按钮和抽屉式目录，避免压缩正文。
- 正文、现有 front matter、项目元数据卡、阅读进度和文章内容本身不修改。
- 项目列表保留现有项目卡信息，只纳入双栏布局。
- 分类、标签、文章和项目的列表样式各自服务内容，不强行抽象成同一种卡片。

### 11.12 评论区

复用现有 `Giscus.astro`、仓库配置和 `pathname` 映射，不引入 Twikoo 或第二套评论系统。

- 所有公开 HTML 页面都在各自主体内容结束后显示评论区；排除 `404`、RSS、sitemap、robots 等错误页或机器端点。
- 双栏页面的评论区位于右侧主体底部，不放进左侧侧栏。
- 首页评论区位于首页右侧内容流末尾。
- 继续采用“加载评论”按钮，用户主动点击后才连接 giscus；加载后由 GitHub 登录参与讨论。
- 每个路径独立映射 Discussion，不共用错误的固定讨论串。
- 评论失败时保留现有重新加载能力，不阻塞正文阅读。

### 11.13 搜索与其他既有能力

- Pagefind 搜索弹窗、索引生成和键盘快捷键保持不变，仅放大导航中的搜索入口图标。
- RSS 继续存在于机器端点，但不在作者卡中显示 RSS 按钮。
- KaTeX、sitemap、固定链接、主题切换和 GitHub Pages Workflow 均不改变。

## 12. 组件与数据边界

建议组件边界：

```text
index.astro
  ├─ 首页 Hero 与打字/滚动行为
  └─ 现有第二屏内容 + 补充后的侧栏与评论区

Nav.astro
  └─ 居中导航、搜索入口与主题入口

ContentSidebar.astro（新增）
  ├─ AvatarCard（统计数量 + Follow Me）
  ├─ AnnouncementWidget
  ├─ RecentPostsWidget（limit=3）
  └─ SiteStats

ContentWithSidebar.astro（新增或最小布局封装）
  ├─ 左侧 ContentSidebar
  └─ 右侧 main slot + Giscus

ArchiveTimeline.astro（可新增，若页面内实现已足够简单则不抽取）
  └─ 年份、日期与文章节点
```

数据继续来自 `publishedPosts()`、`groupByYear()`、`allTags()`、`allCategories()` 和现有文本统计函数，不建立第二套索引。组件只接收展示所需数据；不为一次性页面增加通用主题配置系统。

`Giscus.astro` 保持单实例组件语义。每个页面只渲染一次，不在共享布局和页面本身重复挂载。

## 13. E11：前后对比与保留标准

### 必须满足

1. 桌面端和移动端首屏均严格占满视口，第二屏不能提前露出。
2. `Yilin Blog` 使用当前衬线字体并居中。
3. 两句文案在同一行区域循环打字，不同时出现。
4. 背景保持不变，文字对比依靠局部暗色遮罩，不使用黑描边。
5. 第一次向下滚动直接到现有内容区，后续滚动正常。
6. 首页第二屏右侧内容结构与改造前一致，左侧只出现规格明确允许的补充。
7. 导航始终整体居中；Hero 内透明、离开 Hero 后为圆角悬浮栏。
8. 搜索图标清晰放大，但搜索弹窗和主题图标没有无关变化。
9. 时间轴具有年份、日期、竖线和文章节点，不只是标题改名。
10. 分类总览、标签云和关于页均形成已确认的双栏主体布局，其他公开页面也具有统一侧栏。
11. 作者卡在首页和通用侧栏都显示文章、标签、分类数量，只保留 GitHub `Follow Me` 入口。
12. 公告、最近 3 篇文章和网站资讯按确定顺序显示。
13. 文章详情采用左侧目录与右侧正文并排布局，目录完整出现后阅读辅助区吸顶；项目列表和项目详情继续显示统一侧栏，正文与项目元数据保持不变。
14. 所有公开 HTML 页面主体底部只有一个 Giscus 评论区，仍采用点击后加载。
15. 网站资讯全部来自真实构建数据，不显示虚构访问量。
16. 草稿不进入统计、列表、搜索、RSS 或 sitemap。

### 验证方法

- Vitest：补充导航、Hero 文案、滚动钩子、侧栏内容与数量限制、页面布局范围、评论区唯一性的回归检查。
- Astro check：0 errors、0 warnings、0 hints。
- 生产构建：全部页面和 Pagefind 索引成功。
- 链接检查：Base 路径下新增导航无缺失目标。
- 浏览器桌面端：验证 1440×900 首屏、一次滚轮定位、动画循环、居中导航、五类主体布局、侧栏内容，以及文章目录与正文并排和滚动吸顶行为。
- 浏览器移动端：验证 390×844 首屏、菜单、单行文字边界、时间轴/标签边界、侧栏后置和文章目录抽屉。
- Giscus：至少在首页、时间轴、关于、文章详情和项目详情验证“加载评论”按钮；确认每页只创建一个 iframe 且 pathname 不串页。
- `prefers-reduced-motion`：动画关闭但信息仍可见。
- 截图对比：保留改造前首页，以及改造后首屏、首页第二屏、时间轴、分类、标签、关于和详情页截图。

如果首页第二屏出现无关布局变化、动态文字溢出、滚轮被长期劫持、导航不再居中、评论区重复挂载或移动端正文被侧栏压缩，则不保留实现，回退 E10 对应提交。
